System Architecture

Four parts, one verified chain of trust

Every link below is also a trust boundary. Data only moves forward once it is validated, signed, and — for anything that triggers a real-world action — approved by a person.

Security Controls Map

Every trust boundary, one control each

BOUNDARY 01

Data source → Part 1

Authenticated API keys in a secrets manager, plus anomaly bounds on every inbound reading.

BOUNDARY 02

Part 1 → Part 2

Only validated, corroborated, timestamped data reaches the model.

BOUNDARY 03

Part 2 → Part 3

HMAC-signed threat-cone payload; EXODUS verifies the signature before trusting it.

BOUNDARY 04

Part 3 → real vehicles

RBAC-gated action plus mandatory human approval before emergency mode activates.

BOUNDARY 05

Part 4 → authorities

OAuth2/OIDC login, full audit log of every dashboard action taken.

BOUNDARY 06

Part 4 → citizens

TLS-encrypted, opt-in only, minimal data retained, rate-limited alert delivery.
